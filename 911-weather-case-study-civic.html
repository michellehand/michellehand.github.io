Public systems case study

911 calls in a changing weather context.

A civic data project exploring whether temperature, precipitation, seasonality, and time patterns help explain shifts in emergency call demand.

The goal is not to claim that weather causes emergencies. The goal is to test whether environmental context can improve operational visibility for public safety planning.

Research question

Does weather help explain emergency demand?

911 call volume is shaped by many forces: population activity, time of day, seasonality, holidays, location, infrastructure, and incident type. This project adds one more layer: environmental context.

Primary question

Are there measurable differences in call volume or response demand during heat, cold, precipitation, or other weather conditions?

Operational use case

Could weather-informed features support staffing, preparedness, or public safety resource planning?

Analytical caution

Weather is treated as context, not a single-cause explanation. The analysis controls for calendar and time patterns before interpreting environmental signals.

Data design

Building an event-to-weather dataset.

The project joins emergency call records with weather observations by timestamp and location. The work emphasizes clean timestamps, location-aware joins, and interpretable features.

Method

From raw calls to planning signals.

The workflow is designed to be portfolio-readable: each step can be explained clearly to a technical reviewer, a hiring manager, or a public-sector stakeholder.

Clean and standardize timestamps

Parse call times, normalize date parts, and create consistent hourly or daily aggregation windows.

Aggregate call demand

Summarize calls by time period, call type, priority, precinct or reporting area, depending on available data quality.

Join weather context

Attach weather observations to each time window, then engineer flags for heat, precipitation, cold, and unusual conditions.

Compare baseline vs weather-aware models

Start with time-only baselines, then test whether weather features improve explainability or forecast performance.

Interpretation rule

Any final claim should distinguish between association and causation. A useful operational signal does not need to prove that weather caused the call; it only needs to improve situational awareness responsibly.

Limitations

What this analysis cannot claim.

  • Weather may correlate with activity patterns rather than directly causing incidents.
  • Public call data can contain missing, delayed, or generalized location fields.
  • Call volume reflects reporting and dispatch patterns, not every emergency that occurred.
  • Granularity matters: daily patterns can hide hourly spikes.
